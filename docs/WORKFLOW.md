# Manga workflow

Screenshots of each step, from the bundled *Give My Regards to Black Jack* test series, are in the [README](../README.md#what-it-does) (`docs/images/`).

The chapter screen opens at **Prepare → Translate → Review → Clean → Typeset → Export**. Prepare includes upload, crop, split, auto-crop, alignment, resize, nudging, manhwa reslice, scene notes, and page-edit undo. **Series credits** (optional pre-credits and post-credits) are uploaded on Prepare and stored on the series; **Add credits to this chapter** copies them in as the first and last pages. Auto-crop and auto-align ignore credits when measuring story pages. Auto-align then scales credits to that story width and keeps their proportional height — it does not pad or crop credits. Export warns if the series has a credits page the chapter is missing. Credits pages themselves do not need regions, cleaning, or typesetting to export. Translation tools live on Translate. Export builds a ZIP and can enable a public viewer link. The public viewer shows each page at its export pixel size instead of stretching every page to the same column. Right-click pages or regions for contextual actions; visible Page actions and Region actions buttons expose the same menus. The old destructive cleaning API directs clients to reviewed masks; undo for preexisting pixel backups remains available.

## Automatic transcription and translation

Use **Transcribe chapter** (or **Transcribe page**) to detect lettering and fill source text only. Check and correct the transcription with the existing region tools, then **Translate chapter** (or **Translate page**) to draft English. **Proofread edited English** is optional and never runs automatically.

The persisted transcription job runs these steps in order:

1. Detect text using the chapter's detector and confidence. Chapter runs skip pages that already have regions; page runs re-detect the selected page.
2. Detect a lettering mask once per source page, then white out artwork outside that mask in every crop before Hayai OCR v2 and PaddleOCR-VL-1.6 read it. Region OCR, rereads, and fill-missing OCR use the same masking. Compare letters and numbers while ignoring whitespace, canonical Unicode composition, and interchangeable dashes/tildes.
3. Matching readings fill source only. Disagreements leave source and English empty, mark the region for review, and retain both readings as suggestions with English from the selected Translation model. Existing human/approved/ignored text is preserved. Blank cleanup keeps pending source suggestions.
4. Run council **AI Review** manually for disagreements, or accept a suggestion (its paired English is applied). Chapter translation is not called automatically.

The persisted translation job:

1. Reads existing source lines (ignored and empty-source regions are skipped). It does not detect, describe, or proofread.
2. Translates each page using nearby scene context only: the chapter setting, the previous page note, and the current page note, plus terminology, preferences, and preceding translations from this run. Empty English becomes a draft; existing English is preserved and alternatives appear as suggestions.
3. Human approval is separate from saving: use **Approve & next** to move through the review.

Progress names the current operation. **Stop AI** cancels the work; **Retry unfinished pages** reruns incomplete pages. Job summaries keep the latest request/response entries; older log lines stay on the job up to a retention cap.

**Describe** writes visual scene notes only — no dialogue, SFX, or other lettering. After describing, the proofreading model compacts repeated setting into one chapter summary and leaves each page note with only what is new.

**Fill missing source & English** transcribes only regions that still have no source (Hayai + PaddleOCR-VL), then writes English only where it is still empty: sourced regions with a blank translation, and pending source suggestions that have no English. Existing source and existing English are never overwritten. Use it after drawing boxes or when some pages were transcribed but not translated.

**Optional translation tools** are for intervention: **Proofread edited English** suggests wording changes after you have checked source and drafted English; **Retry uncertain image reading** rereads missing source/English and low-confidence OCR (this can replace text); **Refresh scene context** regenerates scene notes. Nothing is automatically human-approved.

## Source review and Enquire

**Settings → AI models** stores task engines and model IDs on the series. Every chapter uses that set. Description, cheap AI Vision (including Read area), translation, proofreading, the Enquire default, source reviewers, and the Revise English council can each use a different model. The default engine is the fallback before these overrides are saved. Select image-capable models for description, vision, source review, or chats that include images.

Add one to five distinct **Source reviewers**. **AI Review**, beside the Japanese/Korean source, opens the crop first. **Mask crop with detected text** is enabled by default and starts the Clean-step text detector immediately. Detection uses the source pixels. Brush or erase before **Send to local reviewers**, or turn masking off to send the original crop. That send runs local models only (Hayai, PaddleOCR-VL, Qwen3-VL-8B, and configured local HTTP models). Grok, Codex, and Cursor stay idle until you press **Run** on that panel. Each reviewer then sees the same crop independently, without the current transcription or the other reviewers' answers. The dialog shows a panel for each reviewer, with a waiting state, and fills it as that model returns. Matching readings are identified; differences remain visible. Accepting a changed source suggestion preserves original punctuation, clears old OCR confidence, marks the region for review, and automatically sends the corrected text to the configured translation model. Its English replaces the previous draft when ready. The translation does not reread the image. A concurrent edit is preserved and the result becomes a revision-protected suggestion; a failed or cancelled translation keeps the previous English and can be retried in Jobs & downloads.

**Enquire**, beside **Suggest alternative**, opens a model-selectable conversation for the region. **Page Summary**, **Region**, and **Series Summary** start checked. **Region Image**, **Page Image**, and **Chapter Summaries** start unchecked. Region context includes the current saved source and English, type, bounds, OCR metadata, and comments. Legacy generated Source/Literal/Note annotations are excluded so the initial OCR and translation cannot contradict corrected text. Current saved text takes precedence over older conversation suggestions. Series context uses the stored series notes, terminology and translation preferences. Chapter Summaries includes available page summaries from this chapter and preceding chapters, plus chapter terminology; no missing summary is invented. Only checked context and attachments are sent, alongside the advisory system prompt and conversation history.

**Revise English**, between the source box and the English box, opens a council of text translators for that region only. It does not send the crop. Choose up to five translators in **AI model settings → Revise English** (also **Council settings…** inside the dialog). That council is saved on the series, so every chapter uses it. Until that list is saved, the council is the series Translation model plus the Proofreading model when that is a different text translator (a proofreader is skipped — keep that for typeset page images). Hy-MT takes three temperature samples in one request. Grok, Codex, and Cursor stay idle until **Run**. You can add extra local or remote translators for this editor session. Each request includes only glossary terms whose source appears in this balloon, the current English draft, nearby lines, and scene notes. Distinct wordings are saved as English suggestions; accept one to replace the draft. Saving a different council cancels revisions that are still running.

Responses explain wording choices and may provide complete source and English replacement cards. Use or reject each card within the chat. Saved suggestions also appear in the region inspector with their origin. If the region changed since a suggestion was made, the chat shows the current text and requires an explicit replacement decision. Chat history remains available when reopening the same region during this editor session; reloading clears the conversation, while saved suggestions remain. Start **New conversation / change context** to switch the model or context without carrying previously shared context forward.

`POST /api/episodes/:id/region-ai` accepts `review`, `detect-mask`, `revise`, or `enquire`, a region ID and expected revision. Enquiry validates its model, context flags and bounded conversation history. Reviews accept up to five local reviewers and retain successful responses when another reviewer fails. A paid review requires exactly one reviewer and a matching `selectedReviewer: { engine, model }`, sent only by that model's **Run** button. Saved settings alone do not authorize a paid review. Changing reviewer settings cancels pending reviews. Reviews automatically detect a lettering mask when no PNG mask is supplied, unless `maskEnabled: false` explicitly opts out. A supplied PNG mask preserves manual edits; unmasked pixels are whitened before sending. `detect-mask` runs the Clean-step text detector on the source page and returns the region’s mask. `revise` takes one text translator (`model`), optional `samples` (1–5; Hy-MT uses up to three), and `selected: true` for a paid/remote Run. Access requires translation-edit permission and series membership. `GET` serves the authenticated raw region preview without caching; `variant=mask` serves the cropped page mask, or a blank mask of the same size; `variant=comparison` serves the region crop as a two-frame animation (APNG, or GIF with `format=gif`) that alternates the raw and cleaned artwork every 0.5 s, and refuses a page whose cleaned layer is missing or still identical to the raw one. Suggestions use the existing revision-checked accept/reject workflow.

## Working on a chapter

The chapter studio is one screen for all six steps. The top bar is a numbered stepper (progress counts are hidden from the button name), **Find an action** (Ctrl K), the things left to check, save status, **Settings**, and **View**. The page strip shows a status dot for the current step and can filter to to-do or done pages. The stage bar states what the step is for, switches **Page** / **Whole chapter** (the page stays on screen), and holds that step's run buttons, **More**, and model chips. Settings opens one drawer: chapter, text detection, AI models, translation guide, typography, region colours, and series credits, each marked this chapter, series, or just you. Prepare's **Organize** grid reorders pages, selects a range, and adds credits; **Edit page** returns to the canvas. The tool rail is only modal tools. Brush size, grow amount, polygon save, and crop/split/reslice apply sit on the options bar. Page navigation, region/mask/compare, and zoom float over the page. The footer undoes saved edits, marks the page done for this step, and moves to the next page. Review lists the chapter queue. Typeset style shows series, chapter, and region inheritance. Export groups readiness, lists pages by step, and keeps download and public-viewer cards.

1. **Prepare:** upload files, paste images, inspect upload order, optionally stitch strips, and organize pages. On **Organize**, use thumbnail checkboxes (or Ctrl/Cmd-click) for multiple pages, Shift-click for a range, and **Select all** for the chapter. **Delete selected pages** confirms before removing their regions, comments, cleaning and typesetting. **Extract to chapter** prompts for a chapter number, including subchapters such as `12.5`, and copies the selection in reading order to a new chapter in the same series, numbered from `1`. It preserves source/working images, scene notes, transcription, translations, review comments/suggestions, cleaning and text masks, typesetting/layouts, approvals, chapter defaults, and saved workflow document undo/redo and revision history. The source pages stay in place; subsequent page edits are independent. Series settings/fonts remain shared, and chapter-wide job logs and page-organization undo stay with the source chapter. The new chapter has no public preview link until sharing is enabled. Japanese/right-to-left is the new default. Choose Korean/left-to-right for strips. Renumber after inserting, deleting, splitting, or reordering: displayed page names and exports become `1`, `2`, `3`. Internal IDs, stored filenames, and original-name metadata remain stable. Original upload bytes are retained separately from prepared and cleaned PNG assets. **Reslice strips** (canvas tool or page context menu) stitches the selected page with its neighbours and shows that stitch full-width so cuts can be placed on white rows; the view opens on the selected page and each source page boundary is labelled, so a bubble that crossed an old file boundary can be moved onto one page.
2. **Translate:** **Transcribe** compares Hayai and PaddleOCR-VL for every detected region. Drawing a region starts that same Hayai + PaddleOCR-VL comparison on the crop. **Fill missing source & English** backfills empty sources and empty English without touching text that already exists. Correct source or run manual council review on disagreements, then **Translate** to draft English. Series glossary terms that appear in a region's source show as chips under the source box (`source → English`); they are not clickable. SFX dictionary hits remain clickable meaning buttons. The **Translation engine** selector and model override save the translation task only. **AI model settings** selects the other task models, including manual Read area and proofreading. Translation jobs preserve the requested engine and model on retry. Prepare can describe pages; descriptions omit lettering and are compacted so standing setting is stored once. Detection keeps tight lettering bounds separate from bubble geometry. Drag a selected box or its corner handles to adjust it. Use **Reorder reading flow** with a region selected, then click the region that should be next (`x+1`); numbers and flow arrows update. Right-click **Set as region 1** to move a region to the start. Right-click a region and choose Reread image & retranslate to send its crop directly to the image model, bypassing OCR, and replace that region with a reviewable draft. A concurrent edit is preserved and the model result becomes a suggestion. Read area with image model also supports drawing a new crop. OCR confidence, reading order, source readability, category, and approval are structured records. Unreadable regions stay visible. Ignore requires a reason. Searches cover the chapter; page and numbered-region selections stay synchronized. Series/chapter terminology, aliases, scene notes, and translation preferences accompany translation requests.
3. **Review:** approve English, compare AI suggestions, or restore an older text revision as a draft. **AI Review** asks each selected reviewer for an independent source reading and its English translation together. The expanded dialog shows the crop and current text beside the responses; you can mask the crop with detected lettering and tidy it before sending. **Use source & English** saves the displayed pair as one draft without another model call; different translations of the same reading remain separate choices. **Revise English** compares text-only translations of the saved source (Hy-MT samples plus thinking models with glossary/context) without sending the crop. Repeated translation and proofreading preserve existing English; suggestions require explicit acceptance against their recorded revision. Split/merge retains previous text in revision history, and merged regions remain explicitly ignored. Independent text/comment/scene-note drafts survive failed requests and reloads. A conflict shows the saved version and local draft; review it before choosing which to keep.
4. **Clean:** prepare the page, generate the CTD lettering mask or brush/erase it. Committing manual mask edits also approves the saved mask, making it ready for cleaning immediately. An unedited automatic mask still needs inspection and approval. **Grow mask** expands only the clicked continuous mask section by the chosen amount (a temporary toolbar next to the tools defaults to 10px) so leftover borders can be covered after manual edits, without re-running detection. **Fill speech bubble** is a one-click flat fill of an enclosed balloon: flood from the click, fill enclosed lettering holes, contract so the outline is untouched, and paint the sampled background colour onto the working artwork. **Clone stamp** right-clicks a source, then left-click sets the destination offset and drag copies a brush-sized path; the source cursor stays aligned with the brush. **Blur** paints a Gaussian through a feathered brush so inpainted patches blend into a surrounding gradient instead of leaving a hard disc; brush size sets both coverage and blur amount. **Restore** paints the previous saved artwork back through the same feathered brush, so a reconstruction that fixed one area but rewrote another can be masked back without undoing the whole pass; further restore strokes keep using that same previous save. Auto cleaning samples uniform fills and otherwise uses existing LaMa. Big-LaMa, AOT, flat fill, Telea, and clone/patch remain selectable. Clone / patch uses a source offset in native pixels and rejects masked or out-of-image source pixels. Saved mask/artwork edits have persistent undo/redo. Compare shows prepared source. **Compare raw vs cleaned…** in the region right-click menu opens one animated image of that region’s crop — the raw frame and the cleaned frame, each held 0.5 s — as APNG or GIF, with the region-ai URL behind it, a **Save image** link and a copy-link button, so the comparison can be shared without flattening it to a still. Editing a mask invalidates cleaning approval and requires rerunning cleaning from prepared source; clone/patch, blur, and restore can refine the current cleaned asset without changing the mask.
5. **Typeset:** upload TTF/OTF fonts, inspect previews and metadata, set category styles, and use **Auto-fit all text on page** in the Typeset toolbar to fit every eligible region in one action. Locked layouts are skipped; progress and per-region errors appear in Jobs & downloads. Individual fitting is also available. **Keep current layouts** (Typeset chapter panel and Export) accepts stale placements after page alignment or style-schema changes instead of refitting. Defaults are 12 pt and a 10 pt minimum, with series, chapter, and region overrides. Use manual English newlines, leading, padding, fill, outline, alignment, emphasis, rotation, horizontal/vertical skew (whole-layer shear, ±75°, applied about the region centre so text fills slanted bubbles), and Photoshop Warp Text (Arc, Arc Lower, Arc Upper, Arch, Bulge with Bend −100 to 100). Diamond handles on the right and bottom polygon edges drag vertical and horizontal skew; arrow keys on a focused handle nudge 1°, Shift 15°. Warp is a Type → Warp Text envelope of the fitted box, not Type on a Path: glyph outlines are sampled through that envelope in the editor, PNG, and PSD raster, and PSD also stores the native `text.warp` descriptor so Photoshop can re-edit it. Font files are content-addressed versions; replacements receive separate identities. Locking a layout preserves it; later text/font/geometry/style/DPI edits flag it stale. Save overrides before fitting. Bubble geometry is a separate polygon on **Shape & mask** and the Geometry rail. **Fit bubble** uses SAM with the region box and an interior point (or draft points); OpenCV enclosed-interior remains a fallback. Inspect and approve every proposal. Joined double bubbles split along the outline intersection (the two concave cusps), not a midpoint or the narrowest interior radius. Geometry vertices and text-box bounds are editable. Draw a **rectangle** or **oval** beside the polygon tool to replace the selected region's text shape and auto-fit. English edits on Translate, Review, or Typeset refit that region after the draft saves. Changing region type on Translate, Review, or Typeset resets unlocked lettering to that type's style and reflows it when a layout already exists. To hide typeset text that runs behind another balloon, select the behind-text region and use the mask brush, or **Knock out overlapping regions**. White reveals and black conceals, matching a Photoshop layer mask; erase restores visibility. The same mask clips the in-app preview, flattened PNG/JPG, and the PSD text layer.
6. **Export:** resolve missing source/translations/fonts, unapproved cleaning/geometry, overflow, stale layouts, and numbering. A page whose only regions are explicit ignores does not need source, English, geometry, fonts, fitting, or cleaning approval. **Accept all translations** marks every region that already has English as approved and drops leftover suggestions; empty translations stay as blockers. **Approve all geometry** approves every pending bubble interior or text box across the chapter's pages and refreshes readiness; individual approvals remain undoable. **Keep current layouts** clears stale-refit blockers by accepting the pixels already placed (after page alignment, for example) without running Auto-fit. A separately labelled draft ZIP can bypass readiness. PNG is the default; JPG defaults to quality 95 with 4:4:4 sampling. Image ZIPs contain only numbered image files unless **Include metadata and scripts** is checked (off by default); that option adds chapter JSON, the font manifest, English and bilingual scripts, and draft notes. Draft archives remain labelled by their `DRAFT-` filename prefix. Selecting JSON, English, or bilingual format explicitly still exports that selected document. Native dimensions and explicit DPI are preserved. PSD, clean-only PNG, JSON, English, and bilingual scripts remain available. ZIP generation runs as a persisted job and downloads automatically when ready. The Export screen and Jobs & downloads keep a link to the latest ZIP. Starting another export removes the previous zip. The public viewer does not use that zip; it renders the current chapter.

## Layout and PSD contract

`typesetting.ts` shapes uploaded fonts with Fontkit and stores glyph paths, fitted rows, font identity, and a dependency hash. It tests available polygon width across each line's full height, excludes approved tails by polygon geometry, centers the block, and optimizes whole-word wrapping before reducing size in 0.25 pt increments. It never goes below the style minimum or scales glyphs to fit. English dictionary hyphenation is restricted to a word unable to fit alone at minimum size; every resulting fragment gets its own line, without other words. Automatic breaks are stored outside accepted English.

DPI uses imported density between 10 and 2400 where available, otherwise 72, with an explicit chapter override. Points convert to pixels using DPI/72. Editor final preview, transparent text pixels, and flattened PNG/PSD composites use the same shaped SVG. Editor overlays are excluded from exports.

PSD includes hidden original/prepared references, cleaned artwork, an explicit finished composite, and one editable text layer per fitted nonignored bubble. Font PostScript names, sizes, emphasis runs, explicit breaks/hyphens, leading, alignment, paragraph indents, rotation and skew (as the type layer's affine transform matrix, the same data Free Transform → Skew writes, so the layer stays editable), Photoshop Warp Text (TySh `warp` / Type → Warp Text; Type on a Path is not written), and outline effects are recorded. A region text mask is written as that layer's Photoshop layer mask (white reveals, black conceals) so the live type stays editable and the knockout can be refined in Photoshop. Photoshop auto-hyphenation is disabled. A font manifest identifies exact versions; font files are not embedded into the PSD. Install the exact fonts before editing. Raster pixels are supplied explicitly because ag-psd does not render editable text. Target-editor reflow still requires acceptance testing; cross-application text rendering is not promised identical.

Exports snapshot chapter data, font/layout references, prepared/cleaned asset hashes, preferences, and revisions together after source preparation. Jobs are serialized to bound concurrent export memory. PSD pages above 30,000 pixels per side or 80 megapixels fail explicitly; use PNG or split oversized strips. ZIP construction still requires memory proportional to the generated chapter archive.

## Local worker setup

### Codex artwork reconstruction

In **Clean → Method**, select **Codex · reconstruct artwork** to remove masked SFX and reconstruct the artwork behind it. Use the same saved, approved removal mask as the local cleaners. Codex opens a prompt first so you can add notes such as redrawing a missing finger, or edit the reconstruction instructions. Codex then receives artwork crops and matching black/white removal guides, uses its built-in image generation tool, and the server keeps the entire reconstructed crop, including changes outside the mask. Native page dimensions remain unchanged. Large selections are processed in bounded crops with surrounding context; overlapping crops use the latest reconstruction and skip masks already handled by an earlier crop. Reconstruction is interpretive; inspect the result before applying it. Saved results use the existing approval, undo/redo, cleaning passes, job logs, retry and cancellation flow.

This option uses the installed Codex CLI, its existing sign-in and image generation allowance. Set `CODEX_BIN` if needed; `CODEX_MODEL` selects the coordinating model. It requires a CLI with the `image_generation` feature. The availability check verifies CLI support; account access and usage limits are checked by Codex when a run starts. It does not fall back to a separately billed image API or a different cleaner. See [Codex image generation](https://learn.chatgpt.com/docs/image-generation).

`npm run test:codex-cleaning` uses a fixture CLI without spending Codex usage.

### Local artwork reconstruction and editing

**Clean → Method** offers **Qwen-Image-Edit 2511 · edit artwork**, a 20B instruction editor (Qwen-Image-Edit-2511 + Qwen2.5-VL-7B) that takes a crop and a prompt the same way Codex cleaning does, without leaving the machine. It follows the prompt closely and is the local editor the install bundles use.

```bash
.venv-review/bin/python scripts/install-image-edit-model.py       # Qwen-Image-Edit 2511, Q4_K_M default
cmake -S ~/stable-diffusion.cpp -B ~/stable-diffusion.cpp/build-vulkan -DSD_VULKAN=ON -DCMAKE_BUILD_TYPE=Release
cmake --build ~/stable-diffusion.cpp/build-vulkan --target sd-server -j
```

`install-image-edit-model.py` is self-contained: it needs Qwen2.5-VL and the original Qwen-Image VAE, and both land in `data/models/image/qwen-image-edit-2511`. `--quant`/`--encoder` choose the quantization; the 20B transformer plus its 7B encoder is why the default is Q4_K_M and a Q5 encoder. Set `SCAN_IMAGE_SD_SERVER` if the built `sd-server` lives outside `~/stable-diffusion.cpp/build-vulkan/bin`.

The editor runs as its own `sd-server` on port 18092. **Admin → Models → Hardware & services** shows Start/Stop/Restart, and the model panel carries the device picker. It shares a device with the resident chat model: starting the editor unloads the chat models on that device, and starting one of those unloads the editor. A cleaning run starts it on demand and releases it after `SCAN_IMAGE_IDLE_SECONDS` (180 default) without a crop. A load from the Admin panel stays resident. The method reports *unavailable* with the reason (weights not installed, no `sd-server`, port taken, GPU off) instead of falling back to another cleaner.

Each crop is sampled with `SCAN_IMAGE_STEPS` steps and `SCAN_IMAGE_DENOISE` strength, at the model's documented guidance: 20 steps at CFG 2.5 with flow shift 3. `SCAN_IMAGE_<KEY>` sets the shared value and `SCAN_IMAGE_EDIT_<KEY>` overrides it for this editor. Strength 1 repaints the whole marked area; lower values keep more of the original page and can leave marked lettering behind. `SCAN_IMAGE_SEED` makes a run reproducible, and `SCAN_IMAGE_OFFLOAD_TO_CPU=1` streams the diffusion weights from RAM for small cards. The recipe also passes `--vae-tiling`: the 20B transformer plus a 5.4GB encoder leave too little free VRAM to encode a crop's init image in one go, which fails the second crop on a 24GB card with `vae encode compute failed`.

Crops grow past the marked bounds so the model can continue the surrounding line art, are padded by repeating the page's edge pixels rather than white, and are always rounded up to the /32 grid the model needs. `SCAN_IMAGE_MIN_SIDE` (512 default) sets the smallest working size for a crop. The returned crop is copied back only where the mask is set, with a 4 px falloff outside it, so the VAE's reconstruction of the rest of the crop does not soften unmarked artwork.

Style LoRAs load through `SCAN_IMAGE_LORAS` (or `SCAN_IMAGE_EDIT_LORAS`) as `name[:multiplier]` entries resolved inside `SCAN_IMAGE_LORAS_DIR`.

`npm run test:image-edit` covers the prompt contract and the crop/sampling behaviour against a fixture `sd-server`.

### Local cleaners

Keep the original OCR environment and a dedicated workflow environment. CPU setup:

```bash
uv venv --python 3.12 .venv-workflow
uv pip install --python .venv-workflow/bin/python torch torchvision --index-url https://download.pytorch.org/whl/cpu
SAM2_BUILD_CUDA=0 uv pip install --python .venv-workflow/bin/python -r ocr/requirements-workflow.txt
```

`SCAN_WORKFLOW_PYTHON` overrides the workflow interpreter. Without that environment, the worker falls back to `.venv-ocr`, where SAM and Big-LaMa may be unavailable. Model weights download on first use and cache in Hugging Face's normal cache. Local cleaning and segmentation do not require a paid service. Existing optional translation engines retain their own configuration and authentication. Local model readiness checks the configured model service; CLI readiness checks that a launchable executable was found and reports that authentication and model availability are checked by the CLI when run. Discovery never sends absolute executable paths to the browser. An invalid `GROK_BIN` / `CODEX_BIN` / `CURSOR_BIN` / `CURSOR_AGENT_BIN` override is reported instead of silently using another install. Cursor is resolved as `cursor-agent` only.

For AMD acceleration, first verify `/opt/rocm/bin/rocminfo` and that PyTorch can execute a tensor on **each** card. Install the PyTorch/torchvision build matching the verified ROCm runtime in the dedicated environment, then install workflow requirements with `SAM2_BUILD_CUDA=0`. `scripts/install-gpu-torch.sh` creates or updates the workflow and review environments, installs their runtime dependencies, and installs the verified ROCm PyTorch build. Environment setup removes GPU ONNX packages and repairs the CPU ONNX fallback. Do not run the CPU installation command afterward. SAM postprocessing that needs its optional CUDA extension is also disabled at runtime.

LaMa Manga runs `mayocream/lama-manga` (`lama-manga.safetensors`) through PyTorch, using ROCm
or CUDA on the selected cleaning device. It caches the loaded model per device
and accepts varying crop sizes with padding to a multiple of eight. No ONNX
provider or MIGraphX graph compilation is required.
`scripts/install-clean-models.py --model lama-manga` installs its weights and config.
Big LaMa uses the separate `dreMaz/AnimeMangaInpainting` repository and
`lama_large_512px.ckpt` file.
`SCAN_LAMA_CHECKPOINT` overrides the LaMa Manga checkpoint path.

RT-DETR and Comic Text Detector also run as eager PyTorch models in the workflow
worker on the selected GPU, retaining their weights between requests. Install
their native SafeTensors and CPU ONNX fallback with
`.venv-workflow/bin/python scripts/install-detect-models.py`.
CTD's native architecture is downloaded from a pinned BallonsTranslator revision,
verified by SHA-256, and stored with its GPL-3.0 license in `data/models/ctd-native-*`.
ONNX sessions always use `CPUExecutionProvider`; GPU ONNX providers are neither
required nor selected. `SCAN_DETECT_DEVICE=cpu` forces the detector CPU fallback.

The scheduler probes device execution and free memory, prefers the least queued GPU with the most free memory, and serializes jobs per device. Separate GPUs can execute separate page jobs; VRAM is never pooled. `SCAN_GPU_MEMORY_FRACTION` defaults to `0.7`; `SCAN_MODEL_THREADS` defaults to `4`. SAM, LaMa Manga, Big-LaMa, and AOT support the PyTorch device path; OpenCV/masks run on CPU. The interface reports the backend actually used and falls back to CPU when no usable GPU is detected.

## Region types and colors

Region types are the editor's categories (`OT`, `Box`, `System`, `Thought`, `Dialogue`, `Aside`, `ST`, `SFX`, `Note`, `Plain`). Each one carries a label and a color used for region outlines. A series can replace that list with its own dynamic types — any short, printable ASCII id (including ids with no built-in meaning, such as `sfx-2`) plus a name and color. **View → Region colors…** opens the panel: every type gets a per-user color override saved on the account, and a series owner or admin can add, rename, recolor, remove, or reset the series types. Per-user colors win over the series color, which wins over the built-in color; the override applies only to whoever saved it, so the same chapter can be reviewed by two people with different color conventions.

Removing a series type never breaks saved work. Regions that already use it keep their id, stay selectable, and keep a menu entry and a color-panel row, so a region whose type is no longer offered can still be identified and recolored. A region with a removed type falls back to the built-in label for that id, or to the raw id, and falls back to `Plain`'s color unless a user override exists.

Series text styles are keyed by region type id, so each type the series adds gets its own font, size, and style. **Type Settings…** lists the added types alongside the built-ins, `Use for series category` in the region inspector saves the current type's style, and the style loads for every region using that type. A removed type with a saved style stays in Type Settings so its remaining regions keep their typography.

On the canvas, a region's number and type label are drawn inside that region and clipped to its bounds, and only for the currently selected region; region outlines are drawn at 80% opacity. Reading-flow arrows (Review step only, more than one region on the page) are black at 25% opacity. These are editor-only identity cues: exported PNG, JPG, and PSD pixels never include region outlines, labels, or arrows.

`GET`/`PUT /api/me/settings` reads and writes the signed-in account's region colors; `PUT` accepts `{ regionColors }` and keeps unrelated account settings intact. Series types are saved through the normal preferences revision check: `POST /api/episodes/:id/workflow` with `{ action: "preferences", scope: "series", data: { regionKinds } }` (or `regionKinds: null` to go back to the built-ins), which requires ownership of the series or an admin account. The preferences payload's `seriesDefaults.data.regionKinds` is the stored list. A `409` means someone else changed the series types while the panel was open.

## Persistence and API changes

The additive SQLite migrations in `src/lib/server/db/workflowMigration.ts` run transactionally once per schema version at startup. They retain legacy comments while copying the newest `Source: ` comment into structured source. Keep database and image/assets directories together in backups. `SCAN_DATA_DIR` and `DATABASE_URL` support isolated instances.

- Line/comment/scene-note writes use expected revisions. Missing revisions return 428; conflicting updates return 409, retaining browser drafts. Geometry/page/style records use document revisions and persistent history.
- `GET /api/episodes/:id/workflow` supplies state, readiness, suggestions, and a job summary; `?jobs=1&revision=&jobsAt=` returns that summary, or `{ unchanged: true }` when neither the chapter revision nor any job has changed; `?backend=1` probes local execution; `?history=:entity` supplies history.
- Workflow POST actions cover prepare/renumber, preferences, font upload, region/fit/split/merge, mask/geometry/clean, page approval/undo/redo, suggestions, export/cancel/retry.
- `workflow/assets/:hash` serves only assets referenced by an authorized chapter or its series font library/history/jobs. Websocket membership also checks series access. Workflow, job, and suggestion events refresh the editor, with polling for recovery.
- Server restarts mark unfinished jobs interrupted. Translation/proofreading retry skips completed pages and retains suggestions; selection retries reconcile overlapping regions. Cleaning retries reuse a persisted request at its original base revision, so intervening edits produce a conflict. An export job stores only its format and options. The chapter snapshot stays in memory until that server process exits, and a retry during that process reuses it. After a restart, retry exports the chapter's current state. Only the latest export is kept; older zip files are removed. The public preview renders the live chapter and does not depend on those zips. Cancellation stops local model subprocesses, forwards abort to AI/OCR, or stops exports at page boundaries.
- Undo stays until you choose to drop it. Translate, Review, Clean, and Typeset each have a toolbar button, “Clear saved history for this step,” which drops that page’s saved history and marks the page complete for that step. Current text, artwork, and typesetting stay. A later edit of that step opens the page again. Marking pages complete for export does not remove history. Finished PNG/JPG/PSD/clean exports stay closed until every page is marked complete in all four steps; draft image ZIPs and script/JSON handoffs do not wait on those marks. A glossary term counts as used when it appears anywhere in the phrase, including inside a longer name and across a line break. Chapter status is only a progress label.

### Additional independent inpainters

**Manga Inpainting** (`manga-inpainting`) uses Minshan Xie et al.’s [Seamless Manga Inpainting with Semantics Awareness](https://github.com/msxie92/MangaInpainting) (SIGGRAPH 2021), through the IOPaint-compatible `manga_inpaintor.jit` and `erika.jit` structural-line exports. It reconstructs grayscale line art and screentones. The app rejects color pages before processing: a page is grayscale when at least 99.9% of its pixels have an RGB channel spread of at most 3 levels. No automatic grayscale conversion of color pages is performed.

**MI-GAN** (`migan`) uses Picsart AI Research’s [MI-GAN](https://github.com/Picsart-AI-Research/MI-GAN) Places2-512 model through the IOPaint-compatible TorchScript export. It accepts grayscale and color pages, preserves crop aspect ratio, and processes masked crops at up to 512 pixels before restoring their original dimensions. Its weights use the MIT license.

Install either in **Models**, then run its **Inpaint** test to enable it in Clean. Both use native PyTorch on CPU, ROCm, or CUDA through the existing cleaning worker. Models load on demand and retain their selected device while resident. They preserve all pixels outside the removal mask exactly and save model IDs and elapsed cleaning times for comparison examples.

The installer downloads checksum-verified exports and upstream license notices into `data/models/workflow/<model-id>` (under `SCAN_DATA_DIR` when configured). `SCAN_WORKFLOW_MODELS_DIR` overrides the shared parent directory. Manga Inpainting requires both model files; MI-GAN requires one. Uninstall removes only that model’s directory and receipt. Existing cleaning defaults remain unchanged.

Manga Inpainting’s [license](https://github.com/msxie92/MangaInpainting/blob/main/LICENSE) permits academic, research, and commercial use; it requires preservation of its notices and citation, and written notice to the author for commercial use. The installer retains the upstream notice beside the weights. Exports are obtained from the `Sanster/models` release artifacts, with checksums matching IOPaint’s model definitions pinned at commit `61a759fb3f332bacdce8b2813f4837495c9b86e0`.
